# Client profile fields

Client now uses the canonical snake_case field names in apps/client/profile_fields.py. Existing reg_number, full_name, gender, mobile_telephone, email, picture, created_at and updated_at remain available. Migration 0017 adds the optional profile fields, extends names and registration numbers, and removes fabricated defaults for new contact details. Existing stored values are preserved. New records default to Individual; select Group, Joint or Organization where appropriate. SevenHillsRegistration remains a separate existing registration workflow.

Registration and edit forms group fields into identity, contact/address, work/personal details, next of kin, savings/interests, and group details. The directory links names to a printable full profile. Its filtered CSV export uses canonical headers. The read-only client API exposes the new fields under its existing staff/linked-client permissions. Loan reports continue to use the same client ID, name, gender and registration number.

## Import

The .xlsx import uses headers instead of column positions. full_name and reg_number are required; other fields are optional. It creates new clients and updates existing clients matched by case-insensitive, trimmed reg_number, preserving client IDs and all linked accounts/loans. Blank cells preserve existing values; numeric zero is explicit. Duplicate workbook keys and ambiguous existing keys are skipped. Results show created, updated, unchanged and row errors. The Updates sheet is used when present, otherwise the active sheet is used. Dates accept Excel serial dates, ISO dates, and DD/MM/YYYY. F/M individually normalize to Female/Male. G/C mean Group; J/JT and the literal M/F mean Joint, with gender cleared for non-individual accounts. Migration 0018 adds the Joint type. Missing values remain blank, not invented demographics or balances.

Legacy headers map as follows: BirthDate to date_of_birth; RegDate to registration_date; NextOfKin to next_of_kin_name (a clearly separated trailing phone is split); Recommended_by to referred_by; SaveGoal to savings_goal; Highest_Level to highest_education_level; Savings_Freq to savings_frequency; Min_Savings to minimum_savings_amount; Grp_Members to group_member_count; Grp_Objective to group_objective; Grp_saving_cycle_length to group_savings_cycle_months; Grp_Chair/Grp_Secreatry/Grp_Treasurer to their canonical group roles. Other canonical headers are case/underscore insensitive.

Profession, Type_of_work and Occupation are treated as occupation candidates. Explicit Formal/Informal values map to employment_sector; Student/Child/Unemployed/Retired map to employment_status. Conflicting occupations are reported for review. Group member counts must be whole numbers. Legacy savings cycles need explicit units (1 year or 12 months); canonical group_savings_cycle_months accepts a whole number. Invalid emails, phone numbers, dates, and other invalid rows are reported. Valid rows import independently. Files are not imported merely by applying the schema migration.

Model validation rejects future birth/registration dates, registration before birth, negative savings, and nonpositive specified savings cycle lengths. Amounts are decimal; blank amounts and counts are distinct from zero. Dates of creation and modification remain separate from the client's registration date.
